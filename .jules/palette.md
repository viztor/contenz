## 2024-03-22 - Interaction Scoping and Focus Visibility
**Learning:** In the `@contenz/preview` package, custom UI elements (like `.card`) had global interactive affordances (`cursor: pointer`, hover states) applied via CSS regardless of the underlying HTML tag. This creates a misleading experience for screen reader or keyboard users when a non-interactive element (e.g. `div.card`) looks interactive but cannot be focused or activated. Additionally, custom components often lack native focus indicators, making keyboard navigation difficult to track.
**Action:** Scope interactive CSS states (hover, pointer cursor) strictly to interactive elements (e.g., `a.card` instead of `.card`), and explicitly define `:focus-visible` outlines for custom interactive components (`a.card`, `.nav-link`) to guarantee keyboard accessibility.
