## 2024-05-24 - Interactive Element Affordances in Preview Components
**Learning:** Found a systemic issue in `@contenz/preview` where interactive affordances (like `cursor: pointer`) were applied broadly to `.card` rather than strictly to interactive elements like `a.card`. This misled users about clickability on static elements like error or informative dashboard cards. Additionally, custom elements lacked explicit `:focus-visible` styling, making keyboard navigation difficult to track.
**Action:** When adding global classes in preview components, always scope interactive pseudo-classes (`:hover`, `:focus-visible`) and styles (`cursor: pointer`) strictly to specific interactive element types (e.g., `a.class`, `button.class`) instead of the base generic class. Always define explicit `:focus-visible` outlines for custom interactive components to ensure keyboard accessibility.
